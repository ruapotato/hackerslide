# RT1172 versus RT1176 (and CVM8A / CVM8B / DVMAA)

Sources: IMXRT1170BIEC Rev. 1 05/2025 Table 1 p.6-8 (industrial, B silicon); IMXRT1170IEC Rev. 5 01/2024 Table 1 p.6-8 (industrial, A silicon);
IMXRT1170CEC Rev. 5 01/2024 Table 1 p.6-8 (consumer); AN14716 Rev. 3.0 (A to B migration); PCN 202502019I; errata IMXRT1170ACE Rev. 1.6.
Table 1 was read from the text layer and confirmed against a rendered page (`png/BIEC_p7_table1-007.png`).

## 1. The assumption "both cores" is wrong for the RT1172

| Attribute (Table 1) | RT1176 CVM8x | RT1172 CVM8x | Note |
|---|---|---|---|
| M7 core | 800 MHz | 800 MHz | industrial; with forward body bias and 1.1 V overdrive (Table 11) |
| **M4 core** | 400 MHz | **none ("—")** | RT1172 is single core. Part-number digit "2" = "Single Core Enhanced Feature" (Figure 1) |
| SRAM | 2 MB (1.75 MB with ECC) | same | |
| Parallel LCD and CSI | Yes | Yes | |
| MIPI DSI and CSI | Yes | Yes | |
| GPU2D | Yes | Yes | |
| PXP | Yes | Yes | |
| 1 Gb ENET with TSN (ENET_QOS) | x1 | **none** | the only peripheral row that differs |
| 1 Gb ENET with AVB | x1 | x1 | |
| 10/100 ENET with 1588 | x1 | x1 | |
| Tamper | — | — | only RT1173 has tamper |
| Everything else in Table 1 | same | same | |

So the RT1172 lacks, relative to the RT1176: the Cortex-M4 core and the ENET_QOS (TSN) MAC. It does NOT lack the GPU, MIPI, LCDIF, CAN or the
other Ethernet MACs (the RT1171/RT1175 are the parts without display/GPU).

Second source: Zephyr hal_nxp pinctrl data for MIMXRT1172CVM8A is the RT1176 data with exactly 44 pin-mux nodes deleted, all of them `ENET_QOS_*`
(hal_nxp@964eca29, `mimxrt1173cvm8a-pinctrl.dtsi`, to which `mimxrt1172cvm8a-pinctrl.dtsi` is declared identical). These are listed per pad in
`pinmux.csv` column `removed_on_RT1172_vs_RT1176`. The same data still lists `CM4_IMXRT_TXEV/RXEV` pad functions on the RT1172; with no M4 they
have no use (INFERRED).

Third source: the NXP SDK device files in the same hal_nxp commit. `MIMXRT1172_features.h` and `MIMXRT1176_cm7_features.h` have identical
`FSL_FEATURE_SOC_*_COUNT` values (LPSPI 6, LPI2C 6, LPUART 12, I2S 4, PDM 1, FLEXIO 2, LPADC 2, DAC12 1, FLEXCAN 3, USDHC 2, FLEXSPI 2, USBHS 2,
USBPHY 2, PWM 4, TMR 4, SEMC 1, ENET 2, LCDIF 1, PXP 1) except that the RT1172 file has no `FSL_FEATURE_SOC_ENET_QOS_COUNT`. The RT1172 device
directory has one header set (`MIMXRT1172.h`), while RT1173/1175/1176 have `_cm4` and `_cm7` pairs — consistent with a single core.

Consequences for a design that counted on the M4 (INFERRED from Tables 13/14, not stated as a rule): the low-power set points in which the M7 is
off and the M4 keeps running (set points 11/12 "active") do not exist for a single-core part; the single-core table (Table 14) has only M7-run,
standby-suspend and SNVS modes. Erratum ERR051307 "GPC: STANDBY entry issue on single core parts" (IMXRT1170ACE Rev 1.6) also applies; read it
before designing the sleep path.

## 4. A versus B silicon (…8A / …8B, …AA / …AB)

* The last letter of the part number is the silicon revision. PCN 202502019I (issued 13 Mar 2025) introduces the B revision and lists
  MIMXRT1172CVM8A -> MIMXRT1172CVM8B (and DVMAA -> DVMAB). The PCN states the previous revision is "NOT recommended for new application design".
* What B fixes (AN14716 Rev 3.0 section 2): ERR052351 (the GPIO_AD / GPIO_LPSR / GPIO_DISP_B2 output drivers degrade over time when their
  supply is above 1.98 V — on A silicon NXP's workaround is to run NVCC_GPIO, NVCC_LPSR and NVCC_DISP2 at 1.8 V) and ERR050643 (pull-up
  pulse on those pins during power-up).
* What B adds: ERR052401 — SEMC_CSX1/2/3 output timing is slower than on A; for SDRAM use SEMC_CS0, SEMC_CSX0 or SEMC_RDY as chip select.
* B also changes the ROM (HAB vector table address, ROM API entry), the CHIPID field (MISC_DIFPROG bits [7:4] 1011 -> 1100) and needs
  SDK 25.06 or later, J-Link v8.38 or later. Mask set A = 0P94B, B = 0P79N.
* Electrical data-sheet changes A Rev 5 -> B Rev 1 that touch a schematic: IOH of the AD/LPSR/DISP_B2 bank at 3.3 V drops (-10 -> -9 mA,
  -5 -> -4.5 mA); 1.8 V-mode maximum of NVCC_GPIO(AD)/DISP2/LPSR rises from 1.95 to 1.98 V; the three banks must not be left unpowered
  (about 500 uA leakage each from VDDA_1P8_IN).
* Ball map: identical in A and B data sheets (289/289 balls, checked by script).

**For this board:** a 3.3 V supply on NVCC_GPIO / NVCC_LPSR / NVCC_DISP2 is only free of ERR052351 on the B part (MIMXRT1172CVM8B).
With the CVM8A part named in the request, either those three banks run at 1.8 V or the erratum is accepted.

Not obtained: a B-silicon errata document (the URL pattern IMXRT1170BCE.pdf returned 404); B errata content here comes from AN14716 only.
